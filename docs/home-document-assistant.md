# 생활 문서 촬영·OCR·음성 질의응답

기본 실행은 **등록 양식이 필요 없는 일반 문서 OCR 모드**다. 안내문·가정통신문 등 한 장의 가로 쓰기 문서를 카메라로 촬영하거나 이미지로 불러오면 실제 사진에서 읽은 내용을 제공한다. 촬영 전에는 촬영 화면만, 촬영 성공 후에는 원문 듣기·질문·체크 상태 듣기를 제공한다. 아래의 등록 양식 준비와 승인은 이전 양식 모드 전용이다.

## 바로 실행

이 노트북에는 Ollama `qwen3.5:4b`, Whisper small 모델과 macOS Vision을 실행할 Command Line Tools가 설치되어 있다. macOS의 기본 OCR은 Apple Vision이다. 저장소 루트에서 실행한다.

```sh
PYTHONPATH=src ./venv/bin/python -m docagent.home serve
```

[문서 도우미](http://127.0.0.1:8765)에 접속한다. 다른 버전이 이미 실행 중이면 그 프로세스를 종료한 뒤 새 명령으로 실행한다. 업데이트 뒤에는 브라우저를 새로고침한다. `--template`을 붙이면 이전 등록 양식 모드이므로 일반 문서 시연에는 붙이지 않는다.

Ollama가 꺼져 있다면 별도 터미널에서 실행한다.

```sh
OLLAMA_HOST=127.0.0.1:11434 OLLAMA_NO_CLOUD=1 OLLAMA_CONTEXT_LENGTH=8192 ollama serve
```

새 Mac에서 처음 설치할 때:

```sh
python3 -m venv venv
./venv/bin/python -m pip install -e '.[dev,ocr,speech]'
brew install ollama tesseract tesseract-lang
ollama pull qwen3.5:4b
./venv/bin/python -c "from faster_whisper.utils import download_model; download_model('small', output_dir='outputs/models/whisper-small')"
```

`--llm off --no-speech`를 추가하면 모델 없이 촬영·OCR·읽기를 시험할 수 있다. 일반 문서 모드는 OCR이 필수이므로 `--no-ocr`를 사용하지 않는다. `--port`, `--model`, `--speech-model`로 포트와 로컬 모델을 지정할 수 있다. `--ocr-engine auto`는 macOS에서 Apple Vision, 다른 OS에서 Tesseract를 사용한다. 명시적인 `--ocr-engine tesseract`도 가능하다. macOS 첫 실행은 포함된 Swift 도우미를 로컬 임시 캐시에 컴파일하므로 Command Line Tools가 필요하다(`xcode-select --install`). 최초 다운로드 외에 문서·음성 처리 중 외부 AI를 호출하지 않는다.

## 사용하는 순서

1. **카메라 켜고 시작하기**를 누른다. 시작 확인음이 한 번 들린다. 자동 촬영은 기본으로 켜져 있고 화면에 켜짐/꺼짐이 표시된다.
2. 종이와 색이 다른 배경에 문서를 놓고 네 모서리에 여백을 준다. 느린 비프음은 위치 조정, 빠른 비프음은 촬영 준비다. 경계가 약 0.6초 이상 안정되면 원본 영상으로 자동 촬영한다. 계속 기다리는 경우 **기다리지 않고 지금 촬영**으로 읽기를 시작할 수 있다. 수동 촬영에서는 전체 페이지가 담겼는지 확인하지 못했다는 안내가 나올 수 있다.
3. OCR이 읽을 수 있는 글자를 찾으면 다음 단계로 이동한다. **인식한 원문 듣기**, **문서에 질문하기**, **체크 상태 듣기** 중 원하는 기능을 선택한다. 새 문서가 필요하면 **다른 문서 촬영하기**를 누른다.
4. 질문은 키보드 또는 **마이크로 질문 말하기 → 녹음 마치기**로 입력한다. 인식된 질문을 확인·수정한 뒤 **질문하기**를 누른다. 녹음은 최대 30초다.
5. 소리를 끄려면 **음성 멈추기** 또는 Esc를 누른다. **현재 안내 다시 듣기**로 반복할 수 있다. 화면 읽기 프로그램 사용 시 설정에서 앱의 음성 안내를 끌 수 있다.

Tab / Shift+Tab으로 이동하고 Enter 또는 Space로 버튼을 누른다. 촬영 성공 시 문서 결과 제목으로 초점이 이동한다. 앱 전체를 마이크 명령만으로 조작하는 기능은 아직 없다.

비프음이 들리지 않으면 **카메라·소리 설정 → 비프음 들어보기**를 누른다. 브라우저의 오디오 시작 여부를 표시하며, 노트북 출력 장치와 음량도 확인한다. 음성 안내 중 비프음 볼륨만 낮춘다. 같은 안내는 24초 간격, 다른 안내는 최소 12초 간격이고 상태가 1.5초 유지되어야 발화한다. 짧게 바뀌는 상태는 비프음으로만 알린다.

## 처리 방식과 범위

| 단계 | 현재 구현 |
|---|---|
| 촬영 전 | 긴 변 960px 이하 프레임, 150ms 간격 시도. macOS Vision 문서 검출(다른 OS는 OpenCV)로 가로·세로 문서의 경계·잘림·꼭짓점 움직임 확인 |
| 실제 촬영 | 카메라에 3840×2160을 요청하고 제공된 영상의 긴 변 4000px까지 보존. 미리보기 선명도·A4 비율로 촬영을 막지 않음 |
| 촬영 후 | macOS는 촬영 원본에 Apple Vision 한국어·영어 OCR을 적용하고 문서 밖의 결과를 좌표로 제외. 원근 변환으로 글자를 손상시키지 않음. 다른 OS는 Tesseract 행 OCR |
| 원문 듣기 | 사진에서 인식한 글자를 그대로 읽음. 확신도가 낮은 글자가 포함된 줄은 ‘인식 불확실’ 안내 |
| 질문 | 짧은 문서는 전체 인식문, 긴 문서는 질문·직전 맥락과 관련된 줄 및 이웃 줄을 메모리에서 검색. Qwen이 고른 근거 ID를 검증한 뒤 실제 OCR 구절만 응답 |
| 서명 관련 위치 | OCR에서 ‘신청인 (서명)’ 등 문구를 찾아 문서의 3×3 구역 위치 안내. 펜 끝·실제 서명란 외곽을 실시간 추적하는 기능은 아님 |
| 체크 상태 | 사각 테두리와 옆 글자를 바탕으로 후보를 찾고 내부 잉크량으로 표시 있음·비어 있음·판독 불가를 추정. 이번 범위는 사진 상태 읽기이며 사용자 선택과 재촬영 대조는 포함하지 않음 |
| 음성 질문 | 설치된 faster-whisper small, CPU int8, 한국어 |

경계 검출은 추정이다. 흰 배경 위 흰 종이, 손으로 가린 모서리, 반사·구김·복잡한 배경에서는 탐지하지 못하거나 잘못 찾을 수 있다. 촬영 가능 판정은 OCR 정확도를 뜻하지 않는다. 반사로 지워진 글자나 OCR이 높은 확신도로 잘못 읽은 글자를 모두 잡아내지는 못한다. 표·여러 열·손글씨·회전된 글자는 읽기 순서나 내용이 틀릴 수 있다. 현재 1장씩 처리하며 여러 페이지를 합치지 않는다.

OCR 확신도는 실제 정답률이 아니다. 금액·날짜 등 중요한 정보는 인식된 구절과 사진을 대조할 수 있어야 하며, ‘원문에 없는 답을 생성하지 않는다’는 제한만으로 OCR 오독이 해결되지는 않는다. 체크 후보가 없다는 결과도 체크칸이 없음을 보증하지 않는다. 브라우저 상태·음성 회귀 검사와 합성 문서 검증 외에 실제 카메라 및 시각장애인 사용성 검증이 필요하다.

## 개인정보

원본 사진·OCR·최근 질문은 현재 Python 프로세스 메모리에 두고 새 촬영이나 지우기로 교체한다. 일반 문서 모드는 세션 파일을 저장하지 않는다. Apple Vision 도우미에는 PNG를 표준 입력으로 전달하며 사진 파일을 따로 기록하지 않는다. Tesseract를 선택하면 처리 도중 OS 임시 파일을 사용할 수 있다. 문서·질문·음성은 로컬에서 처리하며 응답에 근거 문구를 포함한다. 공용 노트북에서는 사용 후 문서를 지우고 서버를 종료한다.

## OCR 실패 수정 (2026-11-13)

실제 촬영본에서 종이 대신 배경을 경계로 선택하고, 불확실한 줄 34개/전체 40개를 성공으로 표시하는 문제가 확인되었다. macOS는 Vision 문서 검출과 정확도 우선 OCR로 전환했다. 원근 보정본보다 원본에서 글자가 잘 읽히는 사례를 확인하여 OCR 입력은 원본을 유지하고 문서 밖의 결과만 좌표로 제외한다. 제목 한 줄만 잘 읽혔다고 본문 전체를 성공 처리하지 않도록 신뢰 가능한 글자 비율과 전체 가중 확신도를 함께 검사한다. OCR 확신도는 실제 정확도와 다르므로 이 검사는 보조 수단이다.

실패 사진에서 제목·보유 기간·동의 거부·참여 제한·14세 미만 관련 문구 다섯 개의 인식을 직접 확인했다. 이는 해당 사진의 부분 검증이며 문서 전체 정확도나 일반 문서 성능 지표가 아니다. 남은 오독과 불확실한 줄은 별도로 안내한다. 사용자 사진을 저장소의 테스트 자료에 추가하지 않는다.

[Apple Vision 문자 인식 API](https://developer.apple.com/documentation/vision/vnrecognizetextrequest)를 사용한다. 다른 OS는 Tesseract 경로를 유지하며 그 경로도 다수의 불확실한 글자를 읽기 성공으로 처리하지 않는다.

## 선택 사항: 기존 등록 양식 모드

양식을 정한 후, 빈 페이지 기준 이미지와 검토할 전체 원문, 체크박스 묶음 JSON을 준비한다. 현재는 A4 단일 페이지를 기본으로 한다. `box_mm`는 페이지 왼쪽 위 기준 `[x, y, 너비, 높이]`다. 항목 원문은 페이지 전체 원문에 그대로 포함된 구간이어야 한다.

```json
[
  {
    "id": "consent_1",
    "source_text": "전체 원문에서 그대로 복사한 해당 항목",
    "min_selected": 1,
    "max_selected": 1,
    "options": [
      {"id": "agree", "label": "동의함", "box_mm": [25, 110, 6, 6]},
      {"id": "disagree", "label": "동의하지 않음", "box_mm": [100, 110, 6, 6]}
    ]
  }
]
```

서명란은 별도 `signatures.json` 목록으로 준비한다. `source_text`는 페이지 원문에 그대로 포함되어야 하며 서명과 작성 주체를 뒷받침해야 한다. `before_signing_group_ids`는 위 체크 항목의 실제 ID를 참조한다.

```json
[
  {
    "id": "applicant_signature",
    "role": "applicant",
    "source_text": "신청인 (서명)",
    "box_mm": [125, 247, 65, 13],
    "before_signing_group_ids": ["consent_1"]
  }
]
```

두 예시의 좌표는 형식 설명용이다. 실제 양식에 그대로 적용하면 안 된다. `role`은 `applicant`, `representative`, `staff`, `unknown` 중 하나다. `--signatures`를 생략하면 서명란 정보가 미등록인 상태로 남는다. 검토 결과 서명란이 없는 양식은 빈 목록 `[]`을 명시한다.

```bash
python -m docagent.home draft-template \
  --reference blank.png --text original.txt --groups groups.json --signatures signatures.json \
  --document-id consent-example --version 1 --title '선정한 동의서' \
  --source '공식 원문 출처' --output outputs/consent-bundle
```

이 명령은 `production`의 `draft` 묶음을 만든다. 검토자가 전체 원문, 항목 문구, 선택 규칙, 체크박스·서명란 좌표, 서명 주체, 관련 원문, 빈 기준 이미지와 출처를 확인한 뒤에만 다음 명령을 실행한다.

```bash
python -m docagent.home approve-template \
  --template outputs/consent-bundle/template.json \
  --reviewer '실제 검토자 이름' --confirm-reviewed
python -m docagent.home serve --template outputs/consent-bundle/template.json
```

승인 기록과 이미지 SHA-256은 내용 변경을 감지한다. 검토자 신원이나 법적 효력을 인증하는 기능은 아니다. 원문·이미지·좌표가 바뀌면 다시 검토한다. 이번 작업에서는 실제 동의서를 임의로 승인하지 않았다.

## 기존 등록 양식 모드의 평가와 해석

```bash
python -m docagent.home evaluate \
  --manifest outputs/laptop-demo-20261113/evaluation.json --demo \
  --output outputs/laptop-demo-20261113/results.json
python -m pytest -q
node tests/home/browser_state_check.cjs
node tests/home/audio_check.cjs
```

Node 명령은 추가 npm 패키지 없이 카메라·마이크 비동기 상태와 비프음·발화 제어를 검사한다. 실제 브라우저·카메라·마이크 검증을 대신하지 않는다. Python·Node 회귀 테스트와 합성 데모 생성·평가는 GitHub Actions에도 연결했다.

합성 기본 사례 5건은 정상 1건, 반대 칸·미표시·중복 표시 3건, 흐린 이미지 1건이다. 데이터셋의 성격과 분모를 결과 JSON에 남긴다.

- **오완료율**: 실제 완료가 아닌 사례 중 완료라고 판정한 수 / 완료가 아닌 사례 수. 흐림·판독 불가 정답도 분모에 포함한다.
- **문제 발견율**: 실제 오표시·누락·중복 사례 중 문제를 발견한 수 / 문제 사례 수. 단순 판독 불가를 문제 발견 성공으로 세지 않는다.
- **정상 완료율**: 정상 사례 중 완료라고 판정한 수 / 정상 사례 수.
- **판독 불가율**: 불확실 판정 사례 수 / 전체 사례 수. 전부 거절해 오완료율만 낮추는 문제를 확인한다.

분모가 0인 지표는 `null`이다. 실제 데이터는 `dataset_kind: real`, 정답 검토자 `reviewed_by`, 데이터셋 버전 `dataset_version`을 명시한다. 튜닝에 사용한 문서와 최종 평가 문서를 분리하고, 동의서 종류뿐 아니라 촬영 조건·표시 방식도 다양하게 확보해야 한다.

## 남은 실제 검증

실제 양식 선정·원문/좌표 검토, 사진별 마스킹 정답, 체크 상태 정답셋, 실제 카메라와 스크린리더·시각장애인 사용자 검증이 필요하다. 정상·기울어짐·잘림·흐림·빛 반사 조건에서 잘못된 사진의 통과율과 재촬영 횟수를 측정해야 한다. 현재 품질 검사는 반사를 독립적으로 검출하지 않으며 인쇄 내용 대조만으로 모든 반사 손상을 막을 수 있다고 가정하지 않는다.

로컬 모델의 실제 질문 관련성·근거 없음 판정, 한국어 음성 인식, 처리 시간과 메모리 사용량도 측정 대상이다. 기존 체크 평가 수치를 새 질문·음성 기능의 성능으로 해석하지 않는다. 합성 회귀 테스트는 외부 문서 정확도나 독립 작성 성공률을 증명하지 않는다. 이 MVP는 작성 위치로 손을 유도하지 않으며 서명 진위·법적 유효성을 판정하지 않는다.
