# Step 2 — 객체 탐지 결과와 OCR 연동 작업 보고

- 작성일: 2026-10-06
- 작업 브랜치: `ocr/#2-ocr-intergration`
- 목적: 기존 Roboflow 탐지 결과에 주변 텍스트를 연결해 작성 항목을 구조화하고, 실제 원본·촬영 문서로 동작을 검증한다.
- 이 문서는 텍스트만으로 공유할 수 있으며 사진, 원본 파일, API 키를 포함하지 않는다.

## 1. 작업 결과 요약

**문서 이미지 → 작성 영역 탐지 → 주변 영역 Crop → 한국어 OCR → 항목 구조화 → JSON 저장** 흐름을 구현했다.

실제 문서 299페이지로 연동을 검증하고, 원본 문서가 잘리는 이미지 보정 문제와 로컬 분석이 불필요한 LLM 전송 검사에 걸리는 문제를 수정했다. 자동 테스트는 총 1,346개 통과했다.

현재 단계는 탐지·OCR 연동 MVP다. 실제 입력에서 오탐, 서명란 미탐, 선택지 문구 누락이 확인되어 자동 음성 안내에 바로 사용하기에는 추가 개선과 검토가 필요하다. 이번 작업에서 모델을 재학습하거나 LLM·TTS를 새로 연동하지는 않았다.

## 2. 구현 내용

### 2.1 Roboflow 탐지기 연결

- 기존 탐지기 선택 구조에 `roboflow` 옵션을 연결했다.
- Workflow 응답의 클래스, 신뢰도, Bounding Box를 내부 탐지 형식으로 변환한다.
- `check_box`·`checkbox`와 `signature_field`를 각각 체크박스와 서명란으로 처리한다.
- Roboflow 탐지 신뢰도 기본 기준은 0.5다.
- 분석 CLI 실행 시 `.env`를 읽으며, API 키를 결과 JSON에 포함하지 않는다.

### 2.2 탐지 영역 주변 Crop 및 OCR

- 탐지된 영역 주변에 여백을 추가해 선택지·서명 관련 문구를 함께 읽는다.
- Crop 여백은 왼쪽 45mm, 위 15mm, 오른쪽 45mm, 아래 8mm다.
- 페이지 바깥으로 넘어가는 영역을 제한하고, 겹치는 Crop은 병합한다.
- 로컬 Tesseract의 한국어·영어 OCR을 사용한다.
- Crop 내부 OCR 좌표를 전체 문서의 A4 mm 좌표로 복원한다.
- 주변 영역만 읽는 `regions` 모드와 전체 페이지를 읽는 `page` 모드를 지원한다.

### 2.3 문구와 작성 항목 연결

- 체크박스와 같은 행에 있는 좌·우 문구를 비교해 선택지 라벨을 연결한다.
- 서명란의 왼쪽 또는 위쪽 문구를 이용해 관련 항목을 해석한다.
- 문구가 없거나 연결이 모호하면 임의로 채우지 않고 검토 경고를 남긴다.
- 판단할 수 없는 서명 역할은 `UNKNOWN`으로 유지한다.
- 탐지 신뢰도와 OCR 신뢰도를 별도로 보존하며, 항목 해석에 OCR 신뢰도를 반영한다.

### 2.4 분석 CLI 및 결과 저장

```sh
python -m docagent.analyze blank-form.png --detector roboflow --output outputs/analysis.json
```

결과 JSON에는 탐지 영역, OCR 단어와 좌표, 구조화된 작성 항목, 신뢰도, 검토 필요 여부, 경고, 처리 단계가 포함된다.

분석 진입점인 `analyze_document()`는 이미지 분석 결과를 반환한다. Roboflow를 선택하면 이미지 탐지는 외부 API를 사용하고 OCR은 로컬에서 실행한다. 이 경로에서는 LLM·RAG·음성·펜 이동 장치를 초기화하지 않는다.

CLI는 API 호출 전에 Tesseract 설치와 언어 데이터를 확인한다. API·OCR 실행 오류는 숨기지 않으며, `regions` 모드에서 탐지 후보가 없으면 실패로 알린다. 아래 검증 집계에서는 이를 별도의 ‘탐지 후보 없음’으로 분류했다.

## 3. 실제 문서 검증 방법

### 3.1 데이터 구성

공유된 Google Drive의 하위 3개 폴더를 대상으로 했다. ‘촬영’·‘출력’ 관련 폴더의 사진은 기존 원본을 출력해 찍은 자료로 취급했다.

| 구분 | 수량 |
| --- | ---: |
| 수집 파일 | 219개 |
| 해시가 동일한 중복 파일 | 46개 |
| 중복 제외 파일 | 173개 |
| 원본 파일 | 52개 |
| 촬영본 파일 | 121개 |
| 페이지 단위 전체 입력 | 299장 |
| 원본 페이지 | 162장 |
| 촬영본 페이지 | 137장 |

PDF는 페이지별 이미지로 변환하고, HEIC 사진에는 방향 정보를 적용했다. 촬영본 137장은 제목·레이아웃·내용을 확인해 원본 85페이지와 대응시켰다. 하나의 원본에 여러 촬영본이 연결될 수 있다.

따라서 299장을 서로 다른 양식 299개나 독립적인 외부 테스트 문서 299개로 해석하지 않는다.

### 3.2 실행 조건

- 탐지: 기존 Roboflow RF-DETR Workflow
- 탐지 신뢰도 기준: 0.5 이상
- 정합 해상도: 300dpi
- OCR: Tesseract 5.5.3, `kor+eng`, PSM 11
- OCR 범위: 탐지 영역 주변 Crop (`regions`)
- 동일 입력의 재검증에는 로컬 탐지 결과 캐시 사용
- 중간 API 오류 1건은 한 번 재시도해 해소

## 4. 검증 결과

| 입력 | 전체 페이지 | 탐지 후보 있음 | 탐지 후보 없음 | 최종 API·실행 오류 |
| --- | ---: | ---: | ---: | ---: |
| 원본 | 162 | 119 | 43 | 0 |
| 촬영본 | 137 | 118 | 19 | 0 |
| 합계 | 299 | 237 | 62 | 0 |

‘탐지 후보 있음’은 모델이 후보를 반환했다는 뜻이며, 탐지와 OCR이 모두 정확하다는 뜻은 아니다. 탐지가 있어도 OCR 문구가 없는 사례는 경고로 남겼다. 탐지 후보가 없는 62장에는 안내문·법령 본문 등도 포함되므로 모두 미탐으로 계산할 수 없다.

대응하는 원본과 비교한 촬영본의 탐지 후보 수는 다음과 같다.

| 원본 대비 촬영본 탐지 후보 수 | 촬영본 수 |
| --- | ---: |
| 같음 | 60장 |
| 적음 | 52장 |
| 많음 | 25장 |

후보 수가 같아도 위치·클래스가 틀릴 수 있고, 후보가 많아진 경우 오탐일 수 있다. 이 비교는 촬영 조건에 따른 결과 변동을 확인하기 위한 집계다.

정답 Bounding Box와 정답 텍스트를 구축하지 않아 Precision, Recall, mAP, OCR 문자 오류율은 산출하지 않았다. 학습 데이터와의 중복 여부도 확인되지 않아 외부 일반화 성능 평가로 주장할 수 없다.

## 5. 실제 검증 중 수정한 문제

### 5.1 원본의 큰 표를 문서 테두리로 오인

기존 이미지 보정이 문서 안의 큰 표를 종이 경계로 선택하면서 제목이나 하단 서명란을 잘라내고, 정상 원본을 기울이는 문제가 있었다.

A4 비율과 네 변의 밝은 여백을 함께 확인한 원본은 페이지 전체를 유지하도록 수정했다. 이번 데이터에서 원본 154페이지가 이 조건에 해당했고 촬영본은 해당하지 않았다. 실제 문서 경계를 검출한 경우와 구분해 낮은 보정 신뢰도 및 검토 경고는 유지한다.

학교 동의서에서는 수정 후 하단 서명 표시까지 탐지했지만, 추가 오탐도 존재했다. 잘림 문제를 해결한 것을 모델 전체 정확도 향상과 동일하게 해석하지 않는다.

### 5.2 로컬 분석과 대화 세션 초기화 분리

기존 분석 경로가 대화 세션까지 생성하면서, 항목 ID·순서와 OCR 숫자 조합이 LLM 전송 검사에서 전화번호로 오인되어 중단되는 사례가 있었다.

공통 이미지 분석을 `analyze_document()`로 분리해 분석 CLI가 LLM 전송용 데이터·RAG·장치를 만들지 않도록 수정했다. 실제 대화 세션을 만드는 `build_session()`의 개인정보 전송 검사는 유지했다.

## 6. 남은 한계

| 항목 | 확인 내용 |
| --- | --- |
| 객체 탐지 오탐 | 학교 동의서의 ‘아니요’ 중 ‘요’를 체크박스로 오인 |
| 서명란 오탐·미탐 | 표준근로계약서의 ‘(전화:’를 서명란으로 오인하고, 다른 문서에서는 일부 서명 영역 누락 |
| OCR 누락·오독 | 작은 ‘예’ 문구 누락, 체크박스와 글자가 붙은 영역의 인식 오류 |
| 문구 연결 누락 | 선택지 라벨이 빈 결과가 원본 263/1,088개, 촬영본 445/1,235개 |
| 촬영 조건 변화 | 원근 왜곡·그림자·촬영 각도에 따라 탐지 결과 변동 |
| 문서 형식 | 가로 문서나 여러 면을 한 장에 넣은 자료는 세로 A4 좌표 가정의 한계 |
| 문서 전체 이해 | 주변 Crop만으로 제목·약관·모든 필수 항목을 확인할 수 없음 |

원본과 촬영본의 양식 구성이 달라 빈 라벨 비율 차이를 촬영에 따른 성능 하락률로 해석할 수 없다. 라벨이 채워진 결과도 정확성을 보장하지 않는다. `regions` 결과에는 문서 단위 검토 필요 표시를 유지한다.

## 7. 자동 테스트 및 주요 변경 파일

자동 테스트 **1,346개가 통과**했다. Crop 경계 처리·겹침 병합·좌표 복원·문구 매칭·실패 처리와 로컬 분석 경로 분리를 검증했다. 자동 테스트 통과 수는 실제 모델 인식 정확도와 별개다.

기존 RAG의 NumPy 행렬 연산에서 경고 90개가 발생했으며 별도 확인 대상이다. 이번 분석 CLI 경로에는 RAG가 포함되지 않는다.

| 파일 | 역할 |
| --- | --- |
| `src/docagent/analyze.py` | 분석 CLI와 JSON 출력 |
| `src/docagent/pipeline.py` | 이미지 분석 경로와 대화 세션 생성 분리 |
| `src/docagent/vision/regions.py` | Crop 생성·병합 및 좌표 복원 |
| `src/docagent/vision/ocr.py` | Tesseract OCR 연결 |
| `src/docagent/vision/structuring.py` | 체크박스·서명란 문구 연결 |
| `src/docagent/vision/normalize.py` | 원본 페이지 잘림 방지 |
| `src/docagent/vision/detector_factory.py` | Roboflow 탐지기 선택 |
| `src/docagent/detector/roboflow_detector.py` | Workflow 호출·응답 처리 |
| `docs/ocr-integration.md` | 설치·환경변수·실행·검증 안내 |

## 8. 다음 작업 제안

1. 체크박스와 글자가 붙은 영역의 OCR 및 선택지 라벨 연결을 개선한다.
2. 원본과 촬영본을 묶은 고정 평가 세트를 만들고 정답 박스·텍스트를 작성한다.
3. 서명란과 촬영 조건별 미탐·오탐을 정량적으로 평가한다.
4. 검토 필요 여부를 유지하면서 LLM 문맥 해석과 TTS 안내를 연결한다.

현재까지 Step 2의 탐지·OCR 연결과 실제 입력 검증을 완료했다. 이후 단계에서는 인식 결과의 오류를 처리하고 사용자가 확인할 수 있는 흐름을 함께 구현해야 한다.
