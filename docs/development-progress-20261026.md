# doc-agent 개발 현황과 구현 과정

작성 기준: 2026-10-26

## 어떤 프로젝트인가

시각장애인이 종이문서의 작성 항목을 이해하고, 체크하거나 서명해야 하는 위치를 파악하도록 돕는 프로젝트다. 문서에서 작성 영역을 찾고 주변 글자를 읽은 뒤, 해당 항목에 맞는 안내를 음성으로 제공하는 것을 목표로 한다.

현재는 **문서 탐지·OCR·검수·안내 검색·음성 출력의 공통 기능을 구현했고, 실제 지원 문서의 안내문과 인식 결과를 검증하는 단계**다.

## 어떤 과정으로 구현했나

### 작성 영역을 찾는 모델 구축

먼저 팀원이 국내 문서를 수집하고 체크박스와 서명란을 수작업으로 라벨링했다. 이름이나 전화번호를 쓰는 일반 사각형 입력칸은 제외하고, 실제 선택 기능을 가진 체크박스와 서명 영역을 탐지 대상으로 정했다.

처음에는 74장으로 RF-DETR NAS 모델을 학습했고, 서명란을 놓치는 문제가 확인돼 데이터를 106장으로 늘려 재학습했다. 이후 이 모델을 Roboflow API로 호출해 클래스, 신뢰도, 박스 좌표를 받아오는 코드를 연결했다.

이후 진행한 개발은 학습된 모델을 서비스 코드에 연결하는 작업이다. OCR 연동이나 안내 기능을 만들면서 모델을 추가로 재학습하지는 않았다.

### 탐지한 위치와 문서의 글자 연결

박스 위치만으로는 어떤 항목인지 설명할 수 없어 **Tesseract OCR**을 연결했다. 한국어와 영어를 로컬에서 읽고, 체크박스 옆의 선택지나 서명란 주변의 문구를 탐지 결과와 연결하도록 구현했다.

문서 전체를 읽는 방식과 탐지된 영역 주변만 잘라 읽는 방식을 지원한다. 결과는 작성 항목, 선택지, 좌표, 신뢰도 등을 포함한 JSON으로 저장한다. 문구가 없거나 연결이 모호하면 검토가 필요하다는 표시를 남긴다.

실제 문서를 실행하는 과정에서는 문서 안의 큰 표를 종이 경계로 잘못 인식해 제목이나 서명란이 잘리는 문제가 있었다. 이를 보완해 일정 조건의 A4 원본은 페이지 전체를 유지하도록 수정했다.

### 검증된 안내문을 제공하는 방식으로 설계

초기에는 OCR 결과를 LLM으로 해석하는 방향을 고려했다. 하지만 문서를 임의로 요약하거나 작성 방법을 만들어내면 안 된다는 피드백에 따라, **사람이 원문을 확인하고 승인한 안내문을 찾아 제공하는 방식**으로 구체화했다.

문서 종류·버전·페이지와 주변 OCR 키워드를 비교해 안내문을 찾는다. 조건이 맞으면 승인 문구를 그대로 반환하고, 지원하지 않는 문서이거나 여러 항목이 비슷해 구분할 수 없으면 재확인을 요청한다.

현재 안내 경로는 Rule 기반이다. LLM이 안내문을 새로 생성하지 않으며, 임베딩 기반 RAG 검색은 아직 연결하지 않았다. 문서 종류를 자동으로 확정하는 기능도 남아 있어 별도의 문서 확인 과정이 필요하다.

### 촬영 검사·마스킹·음성 출력 연결

촬영된 문서의 해상도, 흐림, 밝기, 경계, 기울기를 검사하고 문제가 있으면 재촬영을 안내하도록 했다.

Roboflow로 이미지를 보내기 전에는 사람이 검토한 개인정보 영역을 검게 가리도록 했다. 마스킹할 위치를 지정하고 수정하는 로컬 검수 화면도 만들었다. 현재는 사람이 영역을 확인하는 방식이며, 개인정보 위치를 자동으로 찾는 기능은 아니다.

음성 출력은 macOS의 한국어 음성을 사용한다. 고정 안내문 재생, 정지, 반복과 다음·이전 항목 이동을 구현했다. 실제 문서의 검증이 끝나면 이 기능을 통해 안내를 들을 수 있도록 구성했다.

### 실제 문서를 검수하고 평가할 도구 마련

탐지 박스와 OCR 결과를 문서 위에 표시하고, 원문과 안내 초안을 함께 확인하는 검수 자료를 만들었다. 정답 박스와 예측 결과를 연결하면 Precision, Recall, F1 등을 계산하는 평가 도구도 구현했다.

이후 실제 문서 후보를 검토하면서 학습에 사용한 문서와 평가용 문서를 구분했다. 단순히 Roboflow의 test에 들어 있다는 이유만으로 처음 보는 문서라고 판단하지 않고, 과거 학습 이력과 같은 원본의 다른 페이지까지 확인했다.

## 현재 실제로 구현된 수준

전체 목표 흐름은 다음과 같다.

**문서 이미지 → 작성 영역 탐지 → OCR → 문서·항목 확인 → 승인 안내문 검색 → 음성 안내**

| 기능 | 현재 상태 |
|---|---|
| RF-DETR 탐지와 Tesseract OCR | 코드 연결 및 실제 문서 실행 확인 |
| 촬영 품질 검사와 이미지 마스킹 | 구현 완료. 실제 환경과 마스킹 영역의 사람 검수 필요 |
| 고정 안내문 검색 | 공통 기능 구현. 실제 운영용 안내문은 아직 미승인 |
| 음성 출력과 항목 이동 | macOS에서 구현. 실제 문서 전체 흐름 검증은 남아 있음 |
| 검수 화면과 평가 도구 | 구현 완료. 실제 정답 데이터 확정 필요 |
| 실제 펜 장치와 음성 입력 | 연결용 코드 일부가 있으며 실제 장치·사용 환경 검증은 남아 있음 |

현재 후보 문서는 4종이며 안내 초안은 9개다. 다만 **운영용으로 승인된 안내문은 아직 0개**다. 따라서 촬영한 문서를 넣으면 정확한 음성 안내까지 자동으로 완료되는 상태는 아니다.

## 실제 검증에서 확인한 내용

공유된 원본과 촬영본 총 **299페이지**에 Roboflow 탐지와 Tesseract OCR을 적용했다. 이 중 237페이지에서 탐지 후보가 나왔고, 나머지에는 안내문이나 법령 본문처럼 탐지 대상이 없는 페이지도 포함됐다. 이 작업으로 실제 문서에서 연동되는 것을 확인했으며, 서명란 미탐과 작은 선택지 글자 누락 등의 문제도 확인했다.

정답 박스와 정답 텍스트를 만들지 않았기 때문에 이 결과로 정확도를 계산하지는 않았다. 원본을 출력해 찍은 사진도 포함돼 있어 299페이지를 서로 다른 문서 양식 299종으로 보지 않는다.

최근에는 주민센터 문서 중 **전입신고서(세대 모두 이동)**를 추가 후보로 골랐다. 확인한 Roboflow 프로젝트의 학습 이력에서는 해당 서식을 발견하지 못했다. 공식 빈 서식을 확보하고 안내 초안 5개와 박스 초안 11개를 준비했다.

이 문서를 300dpi로 분석했을 때 체크박스 6개와 서명란 2개가 탐지됐다. 다만 정답 박스가 미승인이고 OCR·항목 연결에도 확인할 부분이 있어, 탐지 개수를 정확도로 표시하지 않았다. 이 원본은 이미 개발에 사용했으므로 최종 평가에는 별도 촬영본이 필요하다.

코드 검증은 마지막 전체 실행에서 **1,492개 테스트가 통과**했다. 이는 기능과 오류 처리에 대한 검사이며 실제 문서 인식 정확도를 뜻하지 않는다. RAG 수치 연산 경고는 별도 확인 대상으로 남아 있다.

## 앞으로 남은 작업

1. **지원 문서와 안내문 확정**: 우선 전입신고서의 원문·조건·선택지를 확인하고 안내문을 검토·승인한다.
2. **정답 데이터 작성**: 체크박스와 서명 영역의 기준을 맞추고, 사람이 정답 박스와 텍스트를 확정한다.
3. **실제 인식과 항목 연결 개선**: 서명란 미탐, OCR 누락, 문구 연결 문제를 보완해 승인 안내문과 정확히 연결한다.
4. **통합 흐름 검증**: 실제 문서에서 탐지부터 항목 이동·음성 안내까지 확인한다.
5. **별도 촬영본으로 성능 평가**: 개발 설정을 고정하고 새로운 촬영본으로 탐지·안내 성능과 사용자 편의성을 확인한다.

현재 가장 필요한 작업은 지원 문서의 정답과 안내문을 검수하고, 실제 인식 결과를 그 안내에 정확하게 연결하는 것이다. 사람이 승인하는 작업과 인식 오류를 개선하는 작업을 함께 진행해야 한다.
