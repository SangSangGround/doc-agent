# iPhone 문서 도우미

iPhone은 촬영, 한국어·영어 OCR, 원문 낭독, 한국어 질문 받아쓰기를 처리한다. 읽기와 손끝 추적은 아이폰 안에서 처리한다. 일반 문서에서 사용자가 작성란 탐지용 사진 전송을 직접 선택할 때 한 장의 사진을 맥과 Gemini로 보낸다. 질문 음성은 아이폰에 남는다. 같은 Wi-Fi의 Mac이 OpenAI API에 OCR 글자를 보내 문맥을 검토하고, 사용자가 확인한 질문을 보내 답을 받는다. 시연 대상은 iPhone 13 이상이며 화면 버튼은 iOS 17부터, 물리 볼륨 버튼은 iOS 17.2부터 지원한다.

## iPhone에 앱 설치

1. Mac에 Xcode와 연결할 iPhone에 맞는 iOS 플랫폼 지원을 설치한다.
2. 데이터 전송이 가능한 USB 케이블로 iPhone을 연결하고 잠금을 해제한다. 처음 연결할 때 기기 신뢰와 개발자 모드 안내를 따른다.
3. Xcode에서 `ios/DocAgent.xcodeproj`를 열고 `DocAgent` 타깃의 **Signing & Capabilities → Team**에서 본인 팀을 선택한다. 처음이라면 Xcode 설정에서 Apple 계정으로 로그인한다. Bundle Identifier가 이미 사용 중이면 고유한 값으로 바꾼다.
4. 실행 대상을 연결한 iPhone으로 선택하고 **Run(⌘R)**을 누른다. 설치가 끝나면 홈 화면에서 **문서 도우미**를 연다.

[Apple 실기기 실행 안내](https://developer.apple.com/documentation/xcode/running-your-app-on-simulated-or-physical-devices)

## Mac과 iPhone의 AI 연결

Mac에는 Python 3.10 이상과 OpenSSL이 필요하다. 일반 작성란을 분석할 때는 프로젝트 의존성(OpenCV·NumPy·Pillow)을 설치한 Python을 사용한다. iPhone과 Mac을 기기 간 통신이 허용된 같은 Wi‑Fi에 연결하고, Mac의 인터넷 연결을 확인한다.

1. 처음 설정할 때 저장소 루트에서 아래 명령으로 키 설정 파일을 만든다.

   ```sh
   cp -n .env.cloud.example .env.cloud
   ```

2. Mac의 `.env.cloud`에 `OPENAI_API_KEY`를 입력한다. OCR 문맥 검토와 문서 답변에 사용하는 기본 모델은 `OPENAI_MODEL=gpt-5.6-luna`다. 일반 문서 작성란 분석에는 같은 파일에 `GEMINI_API_KEY`를 추가한다. 키는 Mac에 보관한다.
3. 아래 명령으로 HTTPS 중계 서버를 시작하고 시연 중 터미널을 켜 둔다.

   ```sh
   PYTHONPATH=src python3 -m docagent.cloud_relay --env-file .env.cloud
   ```

4. Mac에서 생성된 `outputs/cloud-relay/pairing.json`을 AirDrop으로 시연용 iPhone에 보낸다. 앱 홈의 **설정 → AI 연결 → 연결 파일 열기**에서 이 파일을 선택한다. 같은 화면에서 JSON 전체를 붙여넣어도 된다. 파일에는 해당 Mac의 인증서 지문과 이번 실행에만 유효한 접속 토큰이 있으므로 시연 기기에서만 사용한다.
5. **연결 확인**을 누르고 처음 나오는 로컬 네트워크 접근 요청을 허용한다. Mac에 연결되고 OpenAI 키가 설정됐다는 안내를 확인한다. 시연 질문을 보내면 키 인증과 모델 사용 권한도 확인할 수 있다. 중계 서버를 다시 시작하면 새 연결 파일을 등록한다.

Wi-Fi를 꺼도 촬영, **전체 원문 듣기**, 지원 기기의 한국어 받아쓰기와 질문 확인을 사용할 수 있다. OCR 문맥 검토와 질문 전송에는 같은 Wi-Fi에서 실행 중인 중계 서버가 필요하다. 연결이 되지 않으면 Mac 터미널에서 서버가 실행 중인지, iPhone에 이번 실행의 연결 파일을 등록했는지 확인한다.

## 문서 한 장 읽기

1. 홈의 **촬영 소리 미리 듣기**에서 탐색음과 촬영 준비음을 들어본다. **카메라로 촬영**을 누르고 휴대폰을 세로로 들어 충전 단자가 몸 쪽을 향하게 한다.
2. “종이 왼쪽이 잘렸어요”라는 안내가 들리면 종이를 그대로 두고 휴대폰을 왼쪽으로 옮긴다. 잘렸던 부분이 더 들어올수록 비프음의 박자가 빨라진다. 네 모서리가 안정적으로 들어오면 긴 확인음이 한 번 울린다.
3. **볼륨 위** 또는 **초점 맞추기**를 누른다. 렌즈와 선명도가 안정됐다는 안내가 오면 **볼륨 아래** 또는 **촬영**으로 직접 찍는다. 원하는 위치를 눌러 초점을 맞출 수도 있다.
4. **전체 원문 듣기**를 누르면 Apple Vision이 읽은 글자를 들려준다. 원본과 해상도·언어 보정 설정을 달리한 두 번째 이미지에서 같은 위치의 문구를 대조한다. **사진 불러오기**도 같은 방식으로 처리한다. 글자가 없는 면은 밝기와 획 흔적을 살펴 종이를 뒤집거나 조명을 바꾸어 다시 촬영하도록 안내한다.

## 촬영한 문서에 질문하기

1. 결과 화면에서 **문서에 질문하기**를 열고 음성 질문 버튼을 누른다. 처음 사용할 때 마이크와 음성 인식 접근을 허용한다. 아이폰에 한국어 기기 내 인식이 준비되어 있어야 한다. 지원 여부나 언어 리소스 때문에 음성 인식을 시작할 수 없으면 같은 화면에서 질문을 직접 입력한다.
2. 질문을 말하고 잠깐 쉰다. iPhone의 Apple Speech가 기기 안에서 전사하고, 앱이 받아쓴 질문을 읽어준다. 맞으면 확인해 보낸다. 다르면 다시 말하거나 글자를 고친 뒤 보낸다. 확인 전에는 받아쓴 질문이 iPhone에 머무른다.
3. 확인한 질문은 같은 Wi-Fi에 있는 Mac을 거쳐 GPT-5.6 Luna로 전달된다. GPT는 현재 페이지의 OCR 글자와 줄 위치, 관련 줄 번호, 최근 최대 8회 문답, 등록된 사례·용어를 이용해 답한다. “그럼 제공받은 곳은?”처럼 이어서 물을 수 있고, 대상을 특정하기 어려우면 되묻는다. 문서 답변의 근거는 **출처 듣기**로 확인한다. 검증된 시연 양식의 준비된 질문은 전송 확인 후 기기에 저장된 원문 근거로 답한다.

## OCR 문맥 검토와 ‘인식 불확실’

문서를 촬영하거나 불러오면 Vision이 먼저 읽어 원문을 표시한다. 문맥을 검토할 줄이 있고 Wi-Fi와 Mac 중계가 준비돼 있으면, 사용자가 질문하기 전에도 현재 면의 OCR 글자와 줄 위치를 OpenAI로 보낸다. 검토가 끝나길 기다리는 동안에도 원문을 들을 수 있다. 연결이 끊겼거나 검토가 실패했다면 Wi-Fi에 다시 연결하고 결과 화면에서 **문맥 검증 다시 시도**를 누른다.

기기 판독 점수가 0.70 이상이고 두 OCR 판독 사이에 충돌이 없는 줄은 경고를 생략한다. 점수가 낮은 줄은 다른 줄에서 문맥을 뒷받침하는 구절을 찾고 그 인용이 OCR 원문과 일치해야 다시 평가한다. 문맥 점수가 0.60 이상이고 `0.70 × OCR 점수 + 0.30 × 문맥 점수`도 0.60 이상이면 경고를 해제한다. 두 판독이 ‘3년’과 ‘5년’처럼 충돌한 줄은 경고를 유지한다. 이 과정은 화면과 낭독의 경고 여부를 결정한다. OCR 원문은 그대로 남으며 점수는 실측 정확도를 뜻하지 않는다.

### 직업훈련 생계비 대부 동의서 시연

이번 시연 기준은 받은 `IMG_2510.heic`에 찍힌 **붙임3, 별지 제3호서식, 2024.1.1. 개정 ‘개인정보의 수집·이용·제공 동의서’**다. 해당 종이를 촬영하거나 사진을 불러온다. [고용노동부 고시 제2023-99호와 서식](https://www.moel.go.kr/info/lawinfo/instruction/view.do?bbs_seq=20231202307)

1. “이거 어떤 서류야?”라고 말한다. 앱이 읽어주는 질문을 확인한 뒤 보내고, 답변에 인용된 원문 줄을 들어본다.
2. “공단은 얼마나 오래 보관해?” 다음에 “그럼 제공받은 곳은?”이라고 묻는다. 답변의 기관과 기간을 촬영한 판본에서 확인한다.
3. “대출 상담을 사칭한 실제 사례가 있어?”라고 물어 사례와 출처를 듣는다. “그럼 내 동의서에서 거부하면 어떻게 돼?”라고 묻고 근거가 촬영한 원문으로 바뀌는지 확인한다.
4. 셀룰러 데이터가 켜진 상태에서 Wi-Fi를 끈다. 원문을 재생하고 기기에서 받아쓴 질문을 확인한 뒤, 같은 Wi-Fi에 다시 연결해 질문을 보낸다.

## 체크·서명 안내

1. 읽기 결과에서 **체크·서명 안내**를 연다. 아이폰은 마지막 문서 한 장의 사진, OCR 결과, 읽던 줄, 질문 대화와 작성 위치를 앱의 파일 보호 영역에 저장한다. 이 작업은 기기 백업에서 제외된다.
2. 등록된 시연 양식이면 기기에서 이번 사진에 맞춘 작성 위치를 보여준다. 일반 문서는 사용자가 **이 사진을 보내 작성란 찾기**를 선택하면 같은 Wi-Fi의 맥을 거쳐 Google Gemini가 작성란을 찾고, 맥의 OpenCV가 실제 작성 공간을 확인한다. 일반 문서의 손끝 안내는 이 초기 분석을 마치면 아이폰 안에서 동작한다.
3. **수집·이용**과 **제3자 제공** 중 원하는 항목에서 *동의함* 또는 *동의하지 않음*을 선택하거나 **신청인 서명 또는 인**을 고른다. 마지막 촬영의 체크 상태도 이 목록에서 들을 수 있다.
4. 후면 카메라에 같은 종이와 한 손의 검지 끝을 보여준다. 안내하는 방향으로 손끝을 옮긴다. 선택한 칸 안에서 잠시 멈추면 도착 안내가 들린다. **다른 칸 선택**으로 돌아가거나, 종이에 직접 표시한 뒤 손을 치우고 **작성 후 새로 촬영**으로 최근 체크 상태를 확인한다.
5. 화면을 잠그거나 앱을 종료한 뒤에는 잠금을 풀고 **문서 도우미**를 연다. 마지막 화면에서 원문 재생이나 **이 칸으로 손가락 안내 이어가기**를 누를 수 있다. 답변을 기다리던 질문은 다시 확인한 후 전송한다. 새 사진을 찍어 교체하거나 결과 화면의 **문서 지우고 홈으로**에서 삭제를 확인하면 이전 작업이 지워진다.

구체적인 시연 순서, 일반 문서 성능, 재생 시험과 실기기 측정의 구분은 [발표자용 검증 정리](../docs/ios-writing-demo-handoff.md)에 있다.

## 개발 검증

Xcode가 설치된 Mac에서 다음 명령으로 Swift 테스트와 앱 빌드를 실행한다. 최초 Xcode 빌드는 고정된 OpenCV 패키지를 다운로드한다. 이 단계에는 공급자 키가 필요하지 않다.

```sh
swift test --package-path ios/DocAgentCore
xcodebuild -project ios/DocAgent.xcodeproj -scheme DocAgent \
  -destination 'generic/platform=iOS Simulator' \
  -derivedDataPath outputs/ios-build CODE_SIGNING_ALLOWED=NO build
```

이번 버전의 실기기 시연은 별도로 확인해야 한다. iPhone에서 한국어 받아쓰기와 VoiceOver를 켜고, 비행기 모드에서도 질문을 듣고 수정할 수 있는지 확인한다. 같은 Wi-Fi로 돌아와 질문을 확인해 보낸 뒤 실제 답변과 원문 낭독을 들어본다. 촬영 테스트에서는 준비 안내 후 종이 한 모서리를 화면 밖으로 옮겼을 때 촬영 버튼이 비활성화되는지도 확인한다.
